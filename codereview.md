# Code Review Report

| Line number | Defect type | Why it is a problem | Proposed fix | Severity |
|---|---|---|---|---|
| 45-49 | Assignment vs comparison | `if (monsters[i]->id = id)` assigns the value instead of comparing it. This makes the condition always true and causes incorrect monster lookup behavior. | Change it to `if (monsters[i]->id == id)`. Also check whether `m == nullptr` before dereferencing. | High |
| 53-59 | Null pointer / invalid state | `findMonster(id)` may return `nullptr`, but `m->health` is used immediately. Calling `attackMonster(99, 20)` in `main()` will dereference a null pointer. | Add a null check: `if (m == nullptr) return 0;`. Also handle negative damage safely. | High |
| 55 | Arithmetic issue | `unsigned int dmg = damage;` converts negative damage values to large unsigned numbers, causing incorrect subtraction and possibly wraparound. | Use `int dmg = damage;` or reject negative values before conversion. | High |
| 63-66 | Loop bounds error | The loop condition `i <= monsterCount` reads one element past the valid range (`monsters[monsterCount]`). This causes undefined behavior and potential memory corruption. | Change the condition to `i < monsterCount`. | High |
| 70-74 | Dangling reference | `std::string label` is a local variable, and the function returns `std::string&`. Returning a reference to a local object causes undefined behavior after the function exits. | Return by value: `std::string getMonsterLabel(int id)`. | High |
| 76-80 | Uninitialized variable | `double sum;` is not initialized before `sum += ...;`. This produces undefined behavior and inaccurate results. | Initialize it as `double sum = 0.0;`. Also guard against `monsterCount == 0`. | High |
| 83-87 | Use-after-free | `delete m;` is called before `m->name` is printed. The program then dereferences freed memory, which is undefined behavior. | Print the name before deletion, or use a separate copy of the data. | High |
| 90-99 | Missing return path | `playerRank()` returns a value only for `score > 1000` and `score > 100`. For other values, the function exits without returning anything, which is undefined behavior. | Add a default return, e.g., `return 0;`, or rewrite the logic with a clear fallback. | Medium |
| 101-109 | Buffer overflow / incorrect deletion | `char* name = new char[10];` and `std::cin >> name;` can overflow the buffer if the user enters more than 9 characters. `delete name;` is also incorrect for arrays and should be `delete[] name;`. | Use `std::string name;` instead of `char*` and read with `std::getline` or `std::cin >> name;` with safe type. Then `delete[]` is not needed. | High |
| 121 | Memory leak | `Monster* bonus = new Monster(...);` is created but never deleted. This leaks memory during program execution. | Use a smart pointer or `delete bonus;` before program exit. | Medium |
| 133 | Shallow copy | `Game copy = game;` copies the `monsters` pointer array shallowly. Then both objects may delete the same `Monster` instances in their destructors, causing double free. | Implement a custom copy constructor / copy assignment operator, or store smart pointers instead of raw pointers. | High |
